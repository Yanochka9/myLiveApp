# Монтаж роликов DetailLab по шаблону

Шаблон и код: `montage/detaillab/` (README там же). Эталон — `examples/leopard.json`.

**Сначала определи формат.** Одно длинное видео / «история», «сторис» → этот шаблон.
Папка с несколькими дублями спикера + подсъёмы / «рилс» → `montage/detaillab/reels/README.md`
(отдельный шаблон рилса 40–55 с: хук с наездом и вспышкой, подсъёмы на слова, инфографика, тот же `look.cube`).
Перед монтажом рилса спросить: нужен ли хук, нужен ли мем. 2D-графика (иконки, рисунки, инфографика) обязательна и планируется в раскадровке.
Отвечать пользователю по-русски, коротко. Готовые файлы отправлять через SendUserFile.

## Что пользователь присылает
- Ссылку на видео в Google Drive (или на папку + «последнее, загруженное в HH:MM»).
- По желанию: что написать в финальной плашке (цена, срок, «Напиши +»), модель авто.
Файлы в Drive открыты по ссылке — качать `curl` через `drive.usercontent.google.com` (так делает `make_video.py`).
ID файла в папке найти через `mcp__Google_Drive__search_files` (`parentId = '<папка>'`, сортировать по `createdTime`).

## Порядок работы
1. Скопировать `examples/leopard.json` в `examples/<name>.json`, вписать `name`, `source_drive_id`.
2. `python3 -I make_video.py prep examples/<name>.json` — скачает, сделает proxy 1080×1920,
   транскрипцию (`words.json`, печатает текст с таймкодами) и листы кадров `sheet_XX.jpg` (каждые 0.5 с с таймкодом).
3. Прочитать транскрипт и листы кадров, составить `edl` — список `[a_start, a_end, v_start|null, zoom, part, plate]`:
   - **Хук первым**: самая цепляющая фраза (страх/экспертиза/цифра) ЦЕЛИКОМ, 6–12 с, plate `"hook"`, part 1.
   - Дальше всё по порядку, **фразы целиком** — не резать слова и смысл. Паузы > 0.5 с скрипт режет сам.
     Убрать только вступления-«воду» («так, суббота, рабочая атмосферка»).
   - **Развороты камеры, палец в кадре, смаз** — закрыть: `v_start` = время чистого плана машины (голос остаётся).
     **`v_start` ставить только на план БЕЗ лица** (и подменять им кусок, где лица тоже не видно, или где лицо
     смазано): если в кадре говорящий, звук и губы должны быть из одного момента (`v_start: null`), иначе губы
     расходятся с речью. Смаз в начале/конце фразы с лицом — вынести в отдельный кусок с планом машины.
   - **Подсъёмы к истории** (папка «подсъемы» рядом со «сторис»; к какой машине — по кадрам и дате съёмки):
     `"broll": {"имя": drive_id}` в конфиге, `prep` делает proxy (HDR→SDR + autograde на каждый клип) и листы `broll_XX.jpg`.
     В edl `v_start` = `["имя", t]` — картинка подсъёма на слово («капот» → капот), голос основной; кусок ≤ длины подсъёма.
     Эталон — `examples/belgee_s50.json`.
   - Последний кусок: конец = последнее слово + **1.0 с** (иначе слово обрежется), затем заставка.
   - `zoom` 1.0 / 1.04–1.08 чередовать на склейках; `part` — номер сторис (10–20 с каждая, по смысловым блокам).
4. `plates`: по плашке на тему, 2 строки ПРОПИСНЫМИ (верх белый, низ золотой), коротко. Последняя — призыв
   («СЛОЖНЫЙ АВТО? / НАПИШИ «+» В ДИРЕКТ» или что попросили). `fix_words` — ошибки распознавания.
5. `python3 -I make_video.py build examples/<name>.json` (~10–15 мин, запускать в фоне).
6. Проверить перед отправкой: листы кадров финала, первый кадр (плашка видна), вспышку после хука,
   **распознать речь в последних 6 с** финала — последнее слово целиком, длина аудио = длине видео.
7. Отправить TikTok + Story_N. Закоммитить конфиг `examples/<name>.json` (правило репо — сразу в main).

## Режим «как в жизни» (`"minimal": true`) — по просьбе директора, «меньше монтажа»
- Ролик в исходном порядке (без переноса хука), режутся только паузы; `edl` — 1–2 куска, `v_start: null`, zoom 1.0.
- Только субтитры по слову + `hook_text` (первые `hook_text_dur` = 5 с — держать подольше) и `end_text` (последние `end_text_dur` ≈ 3.5 с).
  Текст — **та же тёмная плашка с золотой рамкой**, что и в историях (светлая «как в CapCut» не понравилась), ПРОПИСНЫМИ.
- Без плашек тем, вспышек, звуков переходов, смены крупности и заставки. **Без музыки** (`music_vol: 0`). Цвет — `r5_light.cube`.
- Эталон — `examples/lekala.json`.

## Утверждённые решения (не менять без просьбы)
- **Цвет — `assets/grade_client.txt` (утверждён клиентом 03.11.2026, ВСЕГДА по умолчанию).** Строка 1 — HDR(HLG)→SDR
  (ставить до кропа/zoompan), строка 2 — кривая, снятая с примеров клиента (Drive «яна детейлинг пример»), + её правка
  в CapCut (контраст +4, насыщ. −4, оранжевый −12, тени −4, белый +4, чёрный −4, температура −3), переведённая в кривые r/g/b
  **по её скриншоту из CapCut и тому же кадру нашего видео** (попиксельная подгонка, ошибка 17 → 5).
  Запись экрана для этого НЕ годится — искажает цвет (первая попытка дала светлее/теплее, клиент заметил).
  Если клиент снова правит цвет в CapCut: попросить скриншот кадра в CapCut, взять тот же кадр из нашего файла, подогнать.
  Поверх (утверждено 03.11.2026 по превью): **оранжевый −15** (только кожа — `assets/skin_orange15.cube`, генератор
  `assets/skin_orange_lut.py`) и **экспозиция −2 / тени −2** (кривая m). Новые правки цвета — сначала превью кадрами, монтаж после «да».
- **Адаптивный цвет (утверждено 03.11.2026): результат один, исходники разные.** Стиль клиента не кладём «одной маской»:
  сначала каждый клип подравнивается под эталон `assets/grade_ref.json` (рилс «Крашеный элемент», IMG_2509/2510) —
  баланс белого по серым/белым пикселям, яркость кривой по перцентилям (сила 0.65, сдвиг ≤ 0.10, кривая pchip),
  насыщенность слегка — потом общий стиль. Код `montage/detaillab/autograde.py`: в `make_video.py` включено само
  (`"autograde": false` — выключить), в рилсах `AUTO = True` в build.py (`gpre_for(src)` — нормализация на каждый клип).
  Эталон пересчитывать только по просьбе клиента (`python3 autograde.py ref <клипы>`).
  Перед монтажом нового ролика показать 3–4 кадра (разный свет) «одна маска / адаптивно» — `autograde.py norm <клип>`. В `make_video.py` включён сам (если в конфиге нет `lut`); в рилсах — `grade.txt` = этот файл.
  Старые варианты ниже — только по явной просьбе (`"grade": "legacy"` или свой `lut`).
- (старое) `assets/look.cube` — темнее, холоднее, глубокие тени: клиенту НЕ понравился («много теней, серо»).
  Сила LUT — `lut_mix` в конфиге (1.0 — Leopard). Под холодный свет гексагонов LUT на 100 % «душит» картинку —
  для Voyah утверждено 0.45. Перед сборкой сравнить варианты на 2–3 кадрах и **замерить цветовой перекос**
  (G−(R+B)/2 по средним тонам, |x| ≤ 2) — нейтрализация синевы легко уводит в зелень.
- Свой LUT — `lut` в конфиге (файл в `assets/`). `assets/r5_light.cube` — «как Refive», лёгкая сила:
  тени и чёрный кузов глубже, середина чуть темнее, белые чистые, оттенок не трогается. **Для Voyah утверждён он**
  (`"lut": "r5_light.cube", "lut_mix": 1.0`). Refive по замерам: средняя яркость ~78, медиана ~62, чёрный ~0–7, света до 240.
- Плашки — тёмные с золотой рамкой, ПОД субтитрами. Субтитры — строчные белые Montserrat, ниже лица,
  **по одному слову** (`sub_words: 1`). Начало слова подтягивается к реальному началу звука (Whisper опаздывает
  на 0.1–0.5 с) и показывается на 0.08 с раньше. На хуке субтитры на 20 % крупнее.
- Заголовок хука (`hook_title`) — **по умолчанию не ставить**: на Voyah не понравился. Включать только по просьбе.
- **На хуке плашки нет** (`hook_plate_show: false` по умолчанию; plate `"hook"` в edl всё равно нужен — по нему вспышка).
- **Безопасная зона TikTok**: справа от x≈900 (y 980–1700) — кнопки, снизу от y≈1580 — подпись/ник, сверху до y≈230 — поиск.
  **Субтитры и плашки — по центру (x=540)**: сдвиг влево не понравился. Ширина плашки ≤ 720 px (край не дальше x=900),
  длинная строка — шрифт сам меньше. Плашка на y=1290, компактная: Inter Black ≤44, рамка 2 px, радиус 24
  (на Leopard широкая плашка 58 px уходила под кнопки — «тяп-ляп»).
- Плашка темы появляется на смене темы, держится `plate_hold` ≈ 2.5 с и плавно гаснет, чтобы не закрывать машину.
  Последняя (призыв) висит до конца.
- Без стабилизации (давала смазанную полосу по краю).
- **Шумодав RNNoise** (`assets/sh.rnnn`, модель GregorR/rnnoise-models, `denoise: 0.85` по умолчанию): фон −10 дБ, голос −1 дБ
  (громкость держит loudnorm после него). Старый FFT-шумодав (afftdn) фон не убирал и делал голос тише — не использовать.
  **Гейт (agate) не ставить** — на рилсе Geely он глушил тихие слова рассказчика.
- Вспышка + «вжух» между хуком и основной частью; мягкие вспышки + щелчки на смене плашек и на заставке.
- Музыка — из папки Drive «музыка и звуки», тихо, но слышно (music_vol ≈ 0.22), без вокала.
- Экспорт ~9 Мбит/с (156 МБ не открывался в просмотрщике), длина ТикТока — сколько нужно для смысла.

## Цвет по скриншоту CapCut (04.11.2026, рилс Geely EX2) — так делать всегда, когда клиент правит цвет сам
- Попросить **скриншоты** (не запись экрана!) одного кадра в CapCut: «исходник» и «после правки».
- Найти этот кадр в исходниках (корреляция), взять наш кадр после HDR→SDR и подогнать:
  `python3 montage/detaillab/lutfit.py <наш_кадр.png> <скрин_правки.png> assets/<имя>.cube` (кривые + 3D-поправка,
  повторяет и HSL-правки). Проверка: средняя ошибка ≤ 3 из 255.
- CapCut показывает исходник iPhone темнее нашего HDR→SDR (0,42 против 0,51) — поэтому «те же ползунки» у нас светлее.
- Светлее/темнее отдельный дубль — **экспозиция ДО LUT** (`curves=all`, множитель света), НЕ кривая поверх LUT:
  кривая поверх по каналам давала фиолетовый (клиент: «стала фиолетовой»). Проверять оттенок красного в итоге.
- Клиенту показывать превью кадрами; монтировать после «да». Каждую версию проверять цифрами, а не на глаз.
